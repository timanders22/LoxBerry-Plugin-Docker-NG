Docker NG

Docker runs additional programs in self-contained containers on the LoxBerry. Portainer is the web interface for it.

Relation to the „Docker“ plugin

Docker NG is a separate plugin, not an update of the older Docker plugin by M. Miklis. It uses its own folder (dockerng) and its own identifier — both can be installed side by side, and anyone who prefers the original keeps it untouched. The original author has stated that he no longer runs either Docker or a LoxBerry.

The three pitfalls with Portainer

  1. Port 9000 stayed silent. From Portainer CE 2.19 onwards nothing listens on port 9000 without --http-enabled. The container runs, the browser only says „connection refused“ — which looks like a failed installation. The install script sets the flag and additionally exposes port 9443.
  2. The setup token only appears in the log. From 2.43 (respectively 2.39.4) the first-run setup requires a token that is displayed nowhere and expires after five minutes. Two buttons on the Settings tab fetch it, or restart the container and fetch a fresh one.
  3. Portainer cannot be embedded. Its interface sends X-Frame-Options and refuses to be shown inside a frame. That is why the button opens a separate window.

The endpoint for Loxone

It sits in the unauthenticated area so that Loxone can reach it without credentials, and it is protected by a token. The comparison uses hash_equals, that is, in constant time.

The endpoint is read-only. It starts and stops nothing. An endpoint in the unauthenticated area that could stop containers would be an attack surface without any benefit — switching happens in Portainer.

Why there is no MQTT tab

Docker NG runs no service that could publish on a cycle. Loxone fetches the state over the HTTP endpoint. An MQTT path could be added, but it is not built — and therefore not claimed either.

What is not verified

Version 1.0.0 was written on a LoxBerry with Debian trixie and PHP 8. Behaviour on older LoxBerry releases has not been tested — hence LB_MINIMUM=3.0.0.

What 1.2.0 fixes

Five findings reported by a reader, all confirmed against the source:

  • The interface did not start when installed (HTTP 500). The path to dk_lib.php only covered the unpacked archive, where htmlauth/ and html/ sit next to each other. Once installed each lives under its own plugins/ level.
  • The configuration — and with it the token — did not survive a reinstall. There is now a backup next to the config folder, so it outlives the folder being deleted.
  • The log tab stayed empty because nothing ever wrote the file. Note that log/ is a ramdisk on the LoxBerry: the file does not survive a reboot.
  • Sixteen texts were escaped twice and showed HTML entities verbatim.
  • This help is now available in English, and there is an uninstall script.
